# Заметки к версиям

[English version](UPDATE-NOTES.md)

Что изменилось в версии, Bloom показывает в шторке **Что нового**: один раз сам после обновления и в любой момент в **Настройки → Версия**, там же **История обновлений**. Заметки лежат в этом репозитории, в [`update-notes/update-notes.json`](../update-notes/update-notes.json), и Bloom читает их из ветки `main`. В приложение они не вшиты: заметку можно добавить или поправить до релиза и после.

## Два вида заметок

Вид заметки зависит от номера версии.

- **Большая версия** оканчивается на `.0` (`1.1.0`, `2.0.0`): сверху картинка, под ней короткий итог на плашке.
- **Патч** — все остальные (`1.0.1`, `1.1.3`): «В этой версии» и список пунктов.

## Файл

Один объект; ключ — версия без `v`, новые сверху:

```json
{
  "1.1.0": {
    "date": "2026-12-01",
    "image": "1.1.0.png",
    "summary": {
      "ru": "Краткий итог версии одной-двумя фразами.",
      "en": "The version in a sentence or two."
    }
  },
  "1.0.1": {
    "date": "2026-11-20",
    "items": {
      "ru": ["Первое изменение", "Второе изменение"],
      "en": ["The first change", "The second change"]
    }
  },
  "1.0.0": {
    "date": "2026-11-11",
    "summary": {
      "ru": "Встречайте Bloom: SoundCloud, Яндекс Музыка, YouTube Music и ваши файлы в одном плеере.",
      "en": "Meet Bloom: SoundCloud, Yandex Music, YouTube Music and your own files in one player."
    }
  }
}
```

| Поле | У кого | Что писать |
|---|---|---|
| `date` | у всех | День релиза, `ГГГГ-ММ-ДД`. |
| `summary` | большая | Одна-две фразы. |
| `image` | большая, по желанию | Имя файла в `update-notes/assets/` или полная ссылка `https://`. |
| `items` | патч | Список изменений, по одному в строке. |

### Два языка

Любой текст — либо одна строка на оба языка, либо объект с `ru` и `en`. Если одного нет, Bloom покажет другой.

```json
"summary": "Один текст на оба языка"
"summary": { "ru": "По-русски", "en": "In English" }
```

`items` может быть и списком таких текстов. Но два языка двумя списками, как в примере выше, читать проще:

```json
"items": ["Fix: …", { "ru": "Исправлено: …", "en": "Fixed: …" }]
"items": { "ru": ["…", "…"], "en": ["…", "…"] }
```

## Картинка

- Положить в `update-notes/assets/` (папка появится с первой картинкой) и вписать имя в `image`.
- Она занимает всю ширину шторки и сохраняет пропорции; углы Bloom скругляет сам. **1200 × 675** (16:9) чётко смотрится на любом экране.
- PNG, JPG или WebP.
- Без картинки большая версия показывает только итог.

## Как писать пункты

- Одно изменение — одна строка, короткая фраза без точки.
- Что видит слушатель, а не как сделано: «Очередь помнит, где её пролистали», а не «Исправлен QueueBlock».
- Сначала новое, потом изменённое, потом исправления.

## Выпуск версии

1. Заметка — отдельным коммитом:
   ```
   git add update-notes
   git commit -m "Update notes 1.0.1"
   git push
   ```
2. Версия — только строка `version:` в `pubspec.yaml` (`1.0.1+1`; число после `+` в релизе заменит счётчик сборок), коммит называется одним номером:
   ```
   git add pubspec.yaml
   git commit -m "1.0.1"
   git push
   ```
3. Тег публикует релиз (GitHub Actions собирает `.apk` и `.ipa`):
   ```
   git tag v1.0.1
   git push origin v1.0.1
   ```

Заметку можно дописать и после релиза: Bloom перечитывает её при каждом запуске. Секреты подписи Android — в настройках репозитория: `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Без них APK подпишется отладочным ключом и не встанет поверх прошлой версии.

## Проверить заметку до пуша в main

Телефону не видны файлы компьютера, поэтому заметку нужно выложить по ссылке: например, запушить в отдельную ветку. Затем запустить сборку с этой ссылкой:

```
flutter run --dart-define=UPDATE_NOTES=https://raw.githubusercontent.com/use-bloom/mobile/<ветка>/update-notes/update-notes.json --dart-define=UPDATE_FORCE=true
```

`UPDATE_FORCE` открывает при каждом запуске **Что нового** этой версии. Картинку из `image` Bloom всё равно берёт из `main`; пока она там не лежит, впиши полную ссылку `https://`.
